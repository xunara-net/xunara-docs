# 超管手册

超管后台是**独立前端与独立入口**（`/admin/`），使用平台令牌登录，不复用用户控制台的
会话与路由（规范 §43、§94）。

## 登录

- 平台令牌来自服务端环境变量 `XUNARA_PLATFORM_ADMIN_TOKEN`（只监听内网/白名单）。
- 后台使用 `sessionStorage + Authorization: Bearer`，不发 Cookie，因此没有 CSRF 面；
  401 清空失效令牌；403 表示权限或套餐受限，保留身份并展示拒绝原因。
- Break Glass 与独立超管人身份仍是待交付目标；静态平台令牌不是已实现的灾难恢复账号。

## 当前功能

| 页面 | 能力 |
|---|---|
| 总览 | 租户、用户、设备、在线/待审批计数、套餐分布、最近事件；不包含活跃用户或成本遥测 |
| 用户 | 查看/搜索、撤销控制台登录、删除与最后账号/owner 保护 |
| 租户 | 组织列表、切换套餐、查看额度/网段、重新分配网段与删除托管组织 |
| 套餐 | 套餐编辑器：名称、价格元数据、周期、设备/成员/路由/密钥/中继配额及能力开关；未接支付 |
| 中继 | 托管节点列表/筛选、一次性接入令牌、版本保护的期望配置/历史恢复与删除 |
| 审计 | 跨租户查询，按租户与条数筛选；高级过滤与导出尚未接入 |
| 系统 | 版本、组件健康、功能开关、平台 API 状态 |

禁用/解禁、重置密码、额度覆盖、网络池完整编辑、中继分组/成本/调度、灾难恢复
告警等仍需开发。规范 §44–§50 是目标，不是当前页面存在即满足的承诺，详见
[实现台账](../developer/implementation-status.md)。

## 托管中继

中继页面只统计平台注册节点，不包含静态公共 DERP map，空列表不代表没有可用中继。
在线、降级、离线、维护、停用及撤销分开展示；数据来自最近心跳，缺失值显示未知，
不提供流量计费结论。配置保存后由中继后续心跳获取；当前回调只记录收到的配置，
运行时应用及执行回执尚缺，不能把期望状态/限速展示为节点已执行。
停用/维护/撤销与删除需确认；删除长期身份后必须重新注册才能恢复心跳。
配置与用户中心共用版本链，冲突不清草稿：先查看最新配置并确认新基准，再手动保存。
历史恢复会生成新版本，不回退版本号或恢复凭据/遥测；已撤销的服务身份不能重新激活。
历史弹窗在手机上独立滚动，最多展示最近 50 项。具体规则以
[服务端中继配置说明](https://github.com/xunara-net/xunara-server/blob/main/docs/network-console.md#中继配置与历史)
为准。

创建时先选所属租户及有效期。一次性注册令牌只在当前弹窗显示，关闭/离页清除，
不进入浏览器存储、网址或日志；写入受保护配置并按
[中继部署说明](https://github.com/xunara-net/xunara-relay/blob/main/README.md#托管中继注册到控制面)
读取。注册仍受套餐中继额度限制，令牌创建成功不等于节点已经在线。

## 套餐编辑

套餐是数据：新增套餐**不需要**改程序。编辑器保存后立即对新用户生效；已有租户的
套餐变更写入审计。

## 操作纪律

- 任何跨租户操作为高敏操作：先确认目标租户与影响面，操作后核对审计。
- 删除账号保留"最后账号 / 最后 owner"保护，后台应显示拒绝原因而不是静默失败。
- 平台令牌泄露等同全平台失陷：发现泄露立即轮换并检查审计。

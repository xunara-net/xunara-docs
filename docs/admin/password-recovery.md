# 平台辅助生成密码重置码

入口是独立平台后台「用户管理」，不是普通用户中心。现有平台 Bearer 权限允许
生成码；租户 owner/admin、服务 API Key 与匿名均无此权限。静态令牌不是已实现的
独立超管人身份、MFA 或灾难恢复账号。

## 操作顺序

1. 通过可靠的独立渠道核实账号持有人，不能只凭未经验证的联系邮箱。
2. 在用户列表核对网络、登录名、启用状态与本地密码恢复能力，点击「重置密码」。
3. 填写管理原因并勾选已核实持有人。原因仅供审计，不输入密码、令牌、码或证件。
4. 确认生成；仅本次弹窗显示原码，后续只能查询待用状态和到期时间。
5. 向已核实的持有人交付码，并告知其在**所属网络**的可信 HTTPS 恢复页手动输入。
6. 关闭弹窗清除本页原码，清理剪贴板和独立渠道敏感副本，不保存含码截图或工单。

生成前可取消，取消不写入。禁用、本地登录未启用、没有本地密码或缺少版本的
账号不能生成。已有待用码时，再次生成将使原码失效，不是延长同一码的有效期。
勾选只是运营者声明，不代表系统完成证件核验；应依平台自己的可靠核实流程操作。

## 结果与故障

生成不会替用户设置密码，不撤销登录、不冻结网络；有效码兑换才修改密码、
消耗码、撤销该账号全部原浏览器登录并提交必需审计。这些动作同事务；失败
不允许部分更改。其他账号 / 网络、机器 / 中继凭据、API Key、外部绑定均不变。

版本冲突或结果未知时保留原因，先「刷新核对账号」，重新确认身份后才可再生成。
刷新不能取回原码，不自动生成第二个码。用户兑换故障时先尝试新密码正常登录，
再核对是否需要重新生成；不要假设超时等于未提交。

普通改密、禁用 / 解禁与账号删除会使旧码失效。删除或外部方式解绑也不是本功能
的一部分。发现账号被接管时需处理其他凭据，密码恢复不是完整接管恢复。

用户步骤见[忘记密码](../user/password-recovery.md)，迁移 / 备份以
[服务端手册](https://github.com/xunara-net/xunara-server/blob/main/docs/password-recovery.md)
和 [Deploy](https://github.com/xunara-net/xunara-deploy) 为准。应成套备份并停止旧
控制面再升级；开放业务后不得用旧快照覆盖新数据。

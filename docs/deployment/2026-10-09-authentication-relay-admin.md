# 认证故障、中继后台与代码审查验收（2026-10-09）

运行版本：服务端
[`4d5f8d2`](https://github.com/xunara-net/xunara-server/commit/4d5f8d2)，用户控制台
[`10f9deb`](https://github.com/xunara-net/xunara-web/commit/10f9deb)，超管
[`8458bda`](https://github.com/xunara-net/xunara-admin/commit/8458bda)。部署 CI 修复为
[`b175026`](https://github.com/xunara-net/xunara-deploy/commit/b175026)，本轮未改变安装器
或已运行的中继二进制。接口字段以各实现仓库为准，不在文档中心复制契约。

## What changed

- 认证查询区分已确认无效凭据与存储故障。HTTP/gRPC 失败关闭，登录查询与退出故障
  不清 Cookie、不返回假匿名或假成功；Web 保留访问目标并显示可重试的故障页。
  决策见 [ADR-0012](https://github.com/xunara-net/xunara-server/blob/main/docs/adr/ADR-0012-authentication-storage-failures.md)。
- 超管中继页替换路线图占位，接入真实注册列表、筛选、一次性令牌、期望状态、区域、
  限速和删除。一次性令牌仅在弹窗内存中展示，关闭时清理；配额 403 不退出超管。
- 修正租户统计字段、套餐切换请求与套餐目录往返。服务端显式导出中继额度，编辑器
  保留完整额度并剔除只读派生字段，继续遵守写接口的严格解码。
- 注册在同一事务内验证令牌、核对用量、创建长期服务身份并消费令牌；失败不消耗
  凭据。删除只有“消费令牌”的旧写入口，SQLite 和内存共享同一契约。先记录
  [Proposal](https://github.com/xunara-net/xunara-server/blob/main/docs/proposals/2026-10-09-atomic-relay-enrollment.md)，
  再实现 [ADR-0013](https://github.com/xunara-net/xunara-server/blob/main/docs/adr/ADR-0013-atomic-relay-enrollment.md)。
- 用户成员页对齐 owner-only，保护最后 owner，修改需确认，取消/失败显示原角色。
  路由页区分读取故障、未知与空列表；托管 DERP 与客户端 Peer Relay 不再混用，
  读取真实 DERP 配置字段。删掉旧前端类型与错误适配，关键边界补中文注释。
- 修正过期事务和 Webhook 的测试时序依赖，不放宽断言；服务端 CI 加入全量 race。
  部署 CI 使用现存模板变量，分别检查单/多租户，不混入已删除的旧参数。

## Why

本轮将两份新规格、开发规则、文档入口与源码实际数据流进行核对，建立
[实现与审查台账](../developer/implementation-status.md)。旧里程碑、页面占位、接口
存在或后端单测通过，不等于整个新规格已经完成。修复优先围绕身份、数据完整性、
真实交互与错误传播，不为清理而删除官方客户端所需的浏览器授权页面。

## Compatibility impact

- 不修改数据库结构或已发布迁移，不改变官方 Tailscale wire 协议、Noise、Map、
  注册、准入或 DERP 转发。未引入 Headscale，不用当前实现改写规格。
- 产品套餐读响应补充已有中继额度；数值和套餐规则不变。内部中继存储写接口收敛为
  原子注册，产品成功响应与既有配额、重放、过期错误码不变。
- 必需 HTML/协议兼容入口和尚未完成独立 Web 对等的模块仍保留。旧账户业务的
  渐进迁移见 [上一轮验收](2026-10-09-passkey-account-consolidation.md)，不是第二套业务实现。

## Security impact

- Human、Machine、Service 身份不互推，租户凭据不能跨租户注册；错误不泄漏 Secret
  或数据库细节。后台权限仍由服务端执行，UI 角色判断不是授权依据。
- 令牌消费和身份创建一起提交或一起回滚，独立 SQLite 连接也不能突破当前传入的
  中继额度；未过期令牌可在资源/存储恢复后重试。
- 注册审计仍在业务提交后执行，提交后响应丢失恢复、跨模块套餐变更竞争、心跳与
  其他历史查询的故障传播尚未完全闭环。不能把本轮修复包装成所有安全边界已完成。
- 静态公共 DERP 不在托管注册列表里；注册列表为空不等于没有可用中继。
  心跳在线、健康上报或图上连线不代表真实客户端连接路径与成功转发。

## Tests

- 在 `xunara-server` 仓库执行的最新 `go build ./...`、`go vet ./...`、`go test ./... -count=1` 与
  `go test -race ./... -count=1` 全部通过。中继存储定向 race 重复 20 次，两个独立
  数据库连接验证数量和单次消费；触发器在身份插入后拒绝令牌更新，验证全部回滚。
- 真实 SQLite 关闭/取消、人类与服务身份、HTTP/gRPC、同名 Cookie、退出失败保留
  Cookie、注册错误脱敏/禁止缓存、跨租户与恢复回归通过。认证事务过期和 Webhook
  确认测试分别重复 100 次通过；之前的偶发失败被记录并修复，不以跳过测试换绿灯。
- 用户控制台 86 项、超管 25 项单元测试、类型检查与生产构建通过。中继仓库源码
  未改，baseline build/vet/test/race 通过；不冒充本轮改变了中继运行协议。
- [可复现脚本](https://github.com/xunara-net/xunara-admin/blob/main/scripts/browser-smoke.cjs)
  十四阶段 Chromium 验收通过，使用隔离临时租户，JavaScript 错误为零：认证故障、
  套餐真实持久化、中继接入/心跳/配置/配额/删除、令牌清理、网络四类读故障与恢复、
  成员权限展示/确认/取消/失败保留原值、移动端布局。
  角色取消/失败使用明确标记的注入夹具，不宣称浏览器真实改了后端角色。
- 通行密钥八阶段回归在本轮认证修复上通过，包括虚拟认证器注册/登录/删除、故障
  恢复与重启持久化；后续中继原子注册不改此模块。虚拟认证器不等于实体设备验收。
- 部署 CI 的单/多租户模板渲染、shell 语法、nginx 两种配置及 Compose 配置验证通过。
  修改安装行为不在本轮范围内，具体验证以部署仓库 CI 为准。
- 首次 GitHub 全量 race 达到默认十分钟整包上限时终止，正在执行的 SSH 用例只运行
  一秒；堆栈显示真实 bcrypt 夹具生成，不是该用例挂起或检测到数据竞争。本地同包
  完整通过但耗时约 599 秒。后续仅调整 CI 为每包二十分钟、作业三十分钟硬预算，
  保留全部用例与真实哈希成本；此配置变更不需要更新已经运行的二进制。

## 调试部署与回滚

先验证现存版本与产物校验和，停止控制面后备份一致状态，原子替换二进制与前端
入口，再检查健康、未登录门禁、租户集合和配置哈希。此次快照保存在
`/root/xunara-rollback/20261009T111218Z-authentication-relay-admin`，目录为 root 专用，
状态归档按机密保存。失败回滚恢复旧二进制及入口，不擅自覆盖用户状态。

升级保留 `default` 与 `team` 两租户、账号、设备、网段和套餐；组织配置、服务单元、
环境文件、nginx 配置、公共中继 map 与证书指纹不变。控制面、中继与 nginx 均 active，
匿名账户/平台 API 拒绝。没有重置用户密码，也没有在生产中创建中继测试记录。

本轮公网验证仅检查匿名浏览器门禁/回跳/移动布局和持有部署凭据的平台只读契约；
凭据只在远端内存使用。它不代替真实生产用户点击、完整数据面或多实例验收。
站点仍为 HTTP 调试环境，不能启用通行密钥，不代表可直接用于正式商业服务；
正式上线还需要稳定 HTTPS 域名与对应安全配置。

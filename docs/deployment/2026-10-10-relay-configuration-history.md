## What changed

- 用户中心与平台后台共享中继配置版本链；编辑、历史恢复和删除携带当前版本前置条件。
- 持久事务复核租户写身份，同事务保存配置、历史、成功审计及配置通知；删除同时清理
  服务身份和对应历史，修正 API Key 范围读取与既有 CSV 持久格式不一致的问题。
- 首次版本写入采集旧配置，查询最近 50 项；恢复生成新版本，不恢复凭据、证书或遥测。
  已撤销身份是终态，历史不能复活；历史损坏/缺字段失败关闭。
- 两个后台冲突保留草稿，展示最新内容并显式确认新基准，随后手动保存；取消不写入。
  历史弹窗支持手机内滚动、固定操作区、键盘焦点与返回，状态文案明确“期望”而非“在线”。

## Why

两个控制台不能静默覆盖彼此修改，审计失败不能留下半次配置发布；只保存历史而不
复核写入者也不能满足撤销/降权安全边界。恢复配置与恢复服务凭据必须严格分离。
配置成功、心跳收到与中继实际执行是不同事实，不通过 UI 文案混为一谈。

## Compatibility impact

无数据库迁移，state v21、identity v13 不变；复用已有历史表，当前中继记录仍是
唯一当前配置权威。首次采集原快照的时间是采集时间，不伪造旧配置的真实编辑时间。
查询/页面最多 50 项不等于已实现持久历史自动清理策略。

管理写请求增加版本要求，旧页面和自动化必须升级：缺前置条件被拒绝，过期版本
返回冲突，不能为兼容旧客户端而自动取最新版本覆盖。先发布服务端，再发布两个前端。
官方 TS2021/Noise/Map/DERP/STUN、Relay 心跳线格式及 opaque 配置版本语义不变；
不改 Headscale、网段分配或套餐判定，Free 默认 10 台设备保持不变。

## Security impact

租户写事务复核持久 Session/API Key、作用域及管理员角色，CSRF 门禁保持；平台
入口只接受独立平台凭据，按解析到的组织选择存储，记录平台来源。只读、过期、
撤销、降权与未知 API 范围拒绝，不以 JSON 猜测既有 CSV 格式。数据库故障不退为空列表。

已撤销身份不能通过普通编辑或历史恢复激活；恢复不覆盖身份与遥测，取消和写点
故障没有部分提交。前端超时不自动重复写入，未知结果需重新读取；401 才清平台
凭据，409/403 不误退出。一次性秘密不放 URL、命令行、报告或日志，离页/关闭即清理。

## 维护升级

完整回归及对应 CI 通过后，关闭 Xunara 公网写入口、排空旧 nginx 工作进程，停止
控制面并保存平台/活动/动态/归档状态、配置及旧产物。维护备份为
`/root/xunara-rollback/20261010T020753Z-relay-configuration-history`（UTC；本文日期为 Asia/Shanghai）。
目录 0700，状态/配置归档 0600，备份含秘密，须按私有权限保留。

只替换服务端及两个前端，先校验原版本/产物再原子替换入口；保留旧哈希静态资源，
不把旧源码混入新构建。`default` 与 `team` 的 state v21/identity v13 不变；逐表摘要
确认用户、密码、身份链接、Session、设备、DNS、中继凭据、网络配置及历史保留。
租户、套餐、网段、域名、组织/环境/服务单元/原 nginx 和公共 DERP map/pin 配置未改。
恢复入口后控制面/中继/nginx active；公共中继进入 active 的时间早于此次维护，未重启。

公网 `/version` 为 `6809d4c`。匿名 Chromium 逐文件核对两个前端与发布 manifest 一致，
权限/DNS/中继/旧 console 需要用户登录，超管入口使用独立平台登录，权限回跳保留；
320/390/768px 登录页面无整体横向溢出，零 JS 错误。配置、地址记录、中继、接入令牌、
配置历史及平台受保护 GET 均为 401。

授权平台只读验证两活动租户和真实中继列表契约，新详情/历史对不存在中继返回 404。
托管注册数仍为零，静态公共中继不是注册记录，不能由零注册数推导没有中继；实际
生产历史编辑/恢复未造数据测试，真实操作由隔离 API/浏览器验收覆盖。
平台凭据只在远端内存经 Authorization header 使用，不进入浏览器、报告或命令行。

本轮不改生产账号密码、不造测试账号/设备/中继，不注入生产故障；临时上传产物
验收后清理，受保护一致性备份保留。升级成功，未执行生产回退。不在线用旧快照
覆盖恢复公网后的新业务，不以只换旧二进制替代一致性恢复。

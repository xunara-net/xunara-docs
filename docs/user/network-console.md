# 网络控制台：先让指定设备安全访问

登录后从左侧菜单进入「我的网络」「访问权限」「DNS」「我的中继」。手机用左上角按钮打开
抽屉，选择后直接显示功能正文。普通成员可以查看，网络所有者或管理员在套餐
允许时编辑；显示为只读不是页面故障。

## 例子：电脑只访问 NAS 的 HTTPS

1. 打开「访问权限」。若提示旧默认设备完全互通，先应用「设备隔离」模板到草稿。
   新的窄规则是允许叠加，不能用它覆盖原有“全部允许”。此时实际权限还没改变。
2. 「添加访问规则」选择来源电脑、目标 NAS，服务选 HTTPS。可选多个设备、成员、
   标签/成员组或高级 IP/CIDR；保存先进入草稿。
3. 点击「测试权限」，选择电脑 → NAS，TCP 443，查看允许原因；改 TCP 22 检查拒绝。
   有草稿时可比较草稿与当前生效策略。这里是编译器权限检查，不是真的发起连接。
4. 「预览并发布」查看增删、警告和策略自检，确认后才生效。NAS 上的服务、端口、
   路由和防火墙仍需实际可达；权限放行本身不会启动服务。

完全互通模板会扩大权限，必须谨慎确认。删除最后一条允许规则并发布表示默认拒绝，
不会自动变回完全互通；不要通过删数据库或重启来“恢复权限”。

## 不同工作方式

| 功能 | 怎么用 |
|---|---|
| 访问规则 | 搜索、创建、编辑、移除来源 → 服务 → 目标的单向允许 |
| 设备图示 | 策略关系图查看同一规则；切换设备创建模式可点击，电脑也可拖动 |
| 权限矩阵 | 选 TCP/UDP 和端口，搜索设备，分别翻来源/目标页；点击允许/拒绝看原因 |
| 设备组 / 成员组 | 创建 tag 所有者与 group 定义；已上报标签成员如实展示 |
| 高级策略 | 编辑 HuJSON、ACL、Grants、SSH、应用能力与测试等支持字段 |
| 历史版本 | 查看已发布记录，预览恢复并确认；恢复生成新版本，不覆盖原历史 |
| 测试权限 | 对指定设备、方向、协议和端口解释生效策略或草稿 |

大网络每次最多显示 8 × 8 权限格，不把几百台设备一次铺满手机。灰色「未检查」
不等于拒绝；自访问显示横线。矩阵结果不是活跃连接或真实拓扑。

设备组不会把机器悄悄改为可信身份：先发布标签授权，再通过带标签的授权密钥或
官方客户端申请标签。无法无损表达的应用能力、多协议/不同目标端口规则使用高级
编辑，避免可视化转换丢失或扩大权限。未知/重复字段和自检失败不能发布。

如果其他管理员先发布，提示版本冲突并保留当前草稿。先自行保留需要的内容，再
刷新最新版本、重新编辑和预览；不要重复点确认强行覆盖。请求超时的结果可能未知，
先刷新确认是否已提交。离开或刷新未保存草稿有确认提示。

## DNS

- **自定义记录**：添加短名或网络域名下的完整名称；A 填 IPv4、AAAA 填 IPv6。
  可编辑或确认删除自己的记录；设备自动名、服务占用名、证书记录不能覆盖。
- **MagicDNS**：启用后用名称访问设备。网络域名仍由部署管理员配置；客户端需接受 DNS。
- **解析器 / 搜索域 / 分流 DNS**：分别填写全局 IP 解析器、短名附加域、指定域的解析器，
  预览整个设置并确认保存。重载和客户端标准配置更新会使用已保存值。
- **设备名称**：查看实际自动名和地址，链接到设备详情；不重复造自定义记录。

分流 DNS 不等于批准路由或允许访问内网 DNS。控制面不是代查 DNS 的服务器，
自建解析器仍需网络可达与权限放行。套餐不允许自定义 DNS 时不可新增/编辑，但
管理员可清理既有自定义记录。当前不支持在 UI 输入未实现的 DoH/DoT 或 TXT/CNAME。

## 我的网络与设备 IP

1. 「我的网络」查看当前实际 IPv4/IPv6 范围；套餐支持自定义时，网络管理员可
   「修改分配网段」，填写 CIDR、「校验并预览」，确认后才保存。
2. 官方设备地址使用 `100.64.0.0/10` 子集，自定义支持 /16～/28；系统保留和
   其他租户历史范围不能使用。`192.168`、`10`、`172` 的家庭/办公网络用于子网
   路由，不作为设备自身 IP。Free 不可改 CIDR，IPv6 当前由系统分配。
3. 保存网段只影响后续分配，已有设备 IP 保持；页面如实显示仍在旧范围的设备数。
   不会一键给所有设备换 IP。需要逐台迁移时，在设备详情点击「修改 IPv4」。
4. 新 IP 必须在实际分配范围内、未被占用且非保留地址；确认后可能中断当前连接。
   MagicDNS/标准节点地图更新沿用控制面；按 IP 写的 ACL、自定义 DNS、应用和外部
   配置需要手工同步。不要把改 IP 误当作自动迁移全部关联服务。
5. 冲突保留输入，关闭并刷新基准后重新确认；网络故障先刷新检查结果。出现待应用
   提示时，设备仍从旧实际范围分配，等待重试收敛，不能重复覆盖或恢复旧数据库。

旧网段和历史设备预留不会因删租户自动释放；安全回收、批量迁移与网段扩容工作流
尚未完整实现，地址池紧张时由运营者审查，不手工清库绕过。

## 我的中继

默认打开「可用中继」，自带中继直接可见，展示地区、端口和默认/平台、非托管/公共、
租户托管来源。「私有中继」是本网络的注册记录；可用地图是客户端实际收到的地区。
两者不能混同，Peer Relay 也不是自建 DERP。没有托管记录不代表没有公共中继。

点击「接入私有中继」生成一次性令牌，保存后关闭立即清除；不能从列表重新读取。
按「接入指南」安装 xunara-relay，填写公网主机、可用地区编号并开放 TLS / STUN 端口。
命令只通过隐藏输入读取令牌，不把它写入链接、参数、shell 历史或页面存储。
令牌发给可信运维人员，未使用时可确认撤销；删除已接入节点会撤销其服务凭证。

### 添加非托管与官方公共中继

1. 进入「非托管中继」，点击「添加或导入公共中继」。手工填地区编号、主机、
   DERP TLS 端口、STUN UDP 端口和可选证书名/pin，再加入草稿；多节点可编辑 JSON。
2. 也可从固定官方 HTTPS 源导入到草稿，保留已有/default 编号，先检查再确认发布。
   导入本身不改变实际地图，不提供任意 URL 的后台抓取。
3. 不能覆盖默认或已登记托管地区，离线/维护托管编号也保留。部署中继策略仍决定
   实际允许哪些地区，不因添加公共节点而绕过租户策略。
4. 外部节点没有 Xunara 服务身份、心跳、远程配置或执行回执，也不消耗托管接入额度。
   “已发布”不表示在线；官方公共服务器是否接纳本平台节点须实际测试，不能保证。
5. 确认「移除地区」只撤回本网络地图，不关闭外部服务器。地图历史可恢复为新版本；
   冲突保留草稿，先刷新最新基准，不能重复确认强行覆盖。

### 托管中继程序下载

「程序下载」已提供直接可运行的预编译文件，**无需安装 Go 或自行编译**。
Linux AMD64/ARM64/ARMv7、macOS Intel/Apple Silicon、Windows AMD64/ARM64 共七种。
请按中继服务器系统与 CPU 选择，不按当前浏览器或手机选择；Linux 可用 `uname -m`。

[真实预览发布与直接下载资产](https://github.com/xunara-net/xunara-relay/releases/tag/v0.1.0-preview.1)
附同版本校验和及源码构建记录。先校验再运行，文件不含接入令牌或账号；校验方法
与 OS 限制以[中继预编译说明](https://github.com/xunara-net/xunara-relay/blob/main/docs/precompiled-release.md)
为准。当前不含 Windows 服务安装器、macOS Apple 签名/公证、签名更新或自动升级，
交叉编译不表示七目标都已完成现场运行验收。下载后再按安全接入指南取得租户授权。

### 配置与恢复

- 点击「管理」修改期望状态、地区显示名与每连接带宽。0 使用节点本地设置，-1
  取消限速，正整数为字节速率；保存前检查影响，撤销服务身份不能恢复启用。
- 两个管理员同时操作时，过期版本不会覆盖最新配置。遇到冲突，草稿保留；点击
  「查看最新配置（保留草稿）」对照，再确认使用最新基准，最后手动保存。
- 点击「历史」查看最近 50 项。选择旧版本并确认「恢复此配置」，它会发布为新
  版本；取消确认不产生写入。冲突时先刷新历史与基准，不重复点击强行覆盖。
- 普通成员可只读查看历史，不能恢复或删除。历史只保存配置，不保存凭据、证书、
  遥测或已删除中继；首次修改前的旧部署操作没有历史可追溯。

保存与恢复的是期望配置，不是节点已经执行的证明。新版托管 Relay 会真实执行并
回报结果：维护拒绝新连接、保留既有连接；停用/撤销主动断开，启用恢复不重启。
0 恢复进程启动时的本地限速，-1 不限速；当前为每连接双向共用额度，不是按套餐
分方向或按租户/用户限速。

「配置执行」分开展示期望版本和「中继上报已应用 / 执行失败 / 待应用」。未升级
节点显示执行未知，超过三分钟的报告显示旧回执；失败显示固定原因与上次成功版本。
实际限速和状态来自服务自报，仍须独立验证真实连接，不把上报当作端到端测试。
撤销后控制面拒绝身份，没有停机 ACK；后台不会用历史回执假称已确认断连。

健康、近期心跳且启用的租户私有节点才加入地图；维护/停用/删除后移除。心跳在线
不代表公网端口、延迟或客户端连接正常；需再实测连接。IP 自签证书使用真实 TLS pin，
不关闭 TLS 校验。旧记录缺少地区/pin 时提示重新接入，不猜测发布；公共发布由超管管理。

## 实现与安全边界

前端全部经同源产品 API 操作，不接触数据库或平台管理令牌。服务器复查租户、角色、
会话、CSRF、套餐和版本；策略/DNS/中继配置的历史与必需审计和写入同事务。接口规则以
[服务端网络控制台说明](https://github.com/xunara-net/xunara-server/blob/main/docs/network-console.md)
为准。正式账号和服务凭据必须通过 HTTPS，不把 HTTP 调试站当成生产安全完成。
完整支付、邮箱找回、细粒度 RBAC、实时诊断和全 OS 实测仍见[实现台账](../developer/implementation-status.md)。

# 登录与注册设置

## 谁可以管理

- **网络所有者**：用户中心侧边栏「登录与注册」。成员页与第三方绑定提示也可直达。
- **平台管理员**：超管后台「登录与注册」，先选择目标租户；租户列表有「登录配置」。
- 普通成员及网络 `admin` 可以管理自己的第三方绑定，但不能改全网应用或准入策略。

这里管理应用与注册，不是个人账号绑定，也不是设备审批。保存后实时生效并持久化，
不需要手工改部署文件或重启服务。

## 开启邀请码加入

1. 在目标网络选择「邀请加入」，保存注册设置。
2. 回到「成员」，创建一次性邀请码，选择允许的 member/admin 角色和有效期。
3. 分别发送页面展示的注册地址和邀请码；邀请者不要把代码拼进网址。
4. 被邀请者在该网络的邀请注册页输入代码，通过密码或已配置第三方登录加入。

关闭邀请不会删除历史；需要永久失效时明确撤销具体邀请。成员额度仍由套餐限制，
Free 的单成员套餐不能靠开启邀请变成多人套餐。邀请不授予 owner。

## 不要混淆两种注册

「成员加入方式」决定谁可以加入**当前网络**。「独立网络公开开户」决定访客能否
注册自己的账户并创建**新的独立网络**；仅开户入口显示，只有平台管理员能修改。
开启成员邀请不会开放共享网络的匿名加入，也不会关闭平台公开开户。
入口租户只允许关闭成员加入或明确邀请，不能开放匿名成员加入。

## 添加第三方登录

1. 点击「添加登录提供方」，选择 GitHub、GitLab、Gitea、通用 OAuth2 或 OIDC。
2. 填写唯一提供方 ID，复制页面显示的固定回调地址，在第三方应用管理页精确登记。
3. 填写真实 Client ID、Client Secret 与对应 issuer/端点。建议先保持停用保存，
   核对应用与回调后再启用。公网提供方可能不接受自签测试证书。
4. 已有成员在「安全中心 → 第三方账号绑定」显式绑定，再用新登录按钮登录。

提供方 ID 和身份域保存后不可修改；换应用/issuer 时用新的 ID。可以修改按钮名称、
启停、轮换密钥或归档。归档清除密钥，但保留绑定记录且 ID 不可复用。
部署来源的提供方可以启停，不能在此覆盖其身份域和运维凭据。

Secret 不回显；提交或离开弹窗会清空，不保存在浏览器存储。配置冲突时保留操作，
先刷新并确认新基准，不覆盖别人的更新。修改配置会取消尚未完成的第三方授权，
需要重新发起；已有控制台会话及设备保持。系统拒绝移除账户最后一种可用登录方式。

## 运维与验收边界

运行时仅接受公网 HTTPS，不能用内网地址、关闭 TLS 校验或禁用 PKCE。配置的
API、存储版本、密封密钥备份及恢复以[服务端手册](https://github.com/xunara-net/xunara-server/blob/main/docs/authentication-settings.md)
为准；升级顺序为 Server → Web/Admin。决策见 [ADR-0029](../../adr/README.md)。

本功能已通过隔离 HTTPS 下真实邀请注册、独立开户、两套配置页面、密钥轮换、
租户隔离、冲突与手机布局验收；真实 OAuth2 回调由隔离提供方验证。没有真实应用
凭据时，不声称已经接通公网 GitHub/OIDC。第三方自动开独立租户、全局账户、
邮箱恢复、2FA 和邮件投递仍是独立待完成项。

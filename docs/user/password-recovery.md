# 忘记密码与平台辅助恢复

当前提供的是平台人工核实后的密码恢复，不是自动邮件找回。联系邮箱未经验证，
不能只凭邮箱属性确认身份，也不能用它合并不同第三方账号。

## 用户操作

1. 联系平台管理员，通过可靠的独立渠道核实你是该网络账号的持有人。
2. 管理员生成重置码后，打开**该账号所属网络**的可信 HTTPS 登录页，点击「忘记密码」。
3. 在恢复页面手动输入完整的一次性重置码、新密码及确认密码，不把它们加到网址中。
4. 成功后返回普通登录页，使用新密码登录。恢复页面不会自动登录。

码有效期为 15 分钟，最多使用一次；重新生成会使先前的码失效。关闭管理员弹窗
后不能重新查看原码。无效、过期、已使用或账号已禁用时，联系管理员重新核对，
不要连续提交。第三方专用账号不会通过此入口新增本地密码。

新密码遵循现有密码策略，要求至少 12 个字符、最多 72 字节且不能等于登录名；
中文和表情会占多个字节。不要向管理员提供新旧密码，也不要在工单、日志或
截图中保存重置码。可信证书的 HTTPS 是正式使用前提，自签测试站需先导入测试 CA。

## 哪些事情会变化

- **生成码**：不改变密码、不退出已有登录，不影响正常使用。
- **成功兑换**：修改本账号的本地密码，撤销本账号全部原浏览器会话，旧码失效。
- **不改变**：组网设备、设备接入 Key、API Key、中继、套餐、DNS / ACL、
  第三方绑定与通行密钥；其他账号、其他网络的浏览器登录不受影响。

第三方绑定和通行密钥仍可重新登录。若怀疑账号被接管，密码恢复不是完整处置，
需进一步检查其他凭据、外部登录方式及设备。禁用账号需要由平台另行解禁；
重置码不能绕过禁用状态。

## 故障时怎么办

读取失败显示故障，不把未知能力当作可用。提交超时或服务故障时，可能无法确认
结果，页面不会自动重试；先尝试使用新密码正常登录，再联系管理员核对待用状态。
重新生成必须显式刷新、核实并确认，不能将未得到响应当作肯定未提交。

恢复码只允许在表单中输入，不提供含码链接。离开页面清除本页输入；如果主动
复制到剪贴板，应在交付后清理剪贴板及独立渠道里的敏感副本。

管理员操作见[平台手册](../admin/password-recovery.md)。权限、接口、数据迁移与
完整安全边界以[服务端说明](https://github.com/xunara-net/xunara-server/blob/main/docs/password-recovery.md)
及 [ADR-0031](https://github.com/xunara-net/xunara-server/blob/main/docs/adr/ADR-0031-platform-password-recovery.md)
为准；邮箱验证、邮件投递、自动邮件找回与完整 2FA 仍未交付。
